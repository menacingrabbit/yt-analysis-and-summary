## High‑level architecture & workflow

The repository is intended to provide a small end‑to‑end pipeline for extracting, transcribing, and summarising YouTube video content.

1. **Entry point** – a CLI script (e.g. `src/main.py`) that accepts a YouTube URL.
2. **Audio extraction** – a thin wrapper around `yt‑dlp` that downloads the best‑quality audio track to a temporary file.
3. **Transcription** – a client module that calls the OpenRouter audio‑to‑text model (e.g. `openai`/`anthropic` SDK). The transcribed text is written to a `data/` folder with a naming convention: `<YYYYMMDD>_<video‑id>_<slug>.txt`.
4. **Summarisation** – another OpenRouter call that summarises the transcript. The summary is saved alongside the transcript (`<slug>_summary.txt`).
5. **Utilities** – small helper modules for:
   - building the filename slug (max 80 characters, date prefix)
   - managing API keys via environment variables (`OPENROUTER_API_KEY`)
   - handling retries / exponential back‑off for network calls.
6. **Tests** – a `tests/` directory containing unit tests for the helpers and integration tests that mock the external APIs.

The overall data flow is:

```
YouTube URL → yt‑dlp → audio file → Transcribe (OpenRouter) → transcript.txt → Summarise (OpenRouter) → summary.txt
```
